Instructions: how to use the calculator
  1. Oracle inputs: list prices, a separate discount for EE, SE2 and each option, support, license model.
  2. Current environment: one row is a group of identical servers (Prod, DR, Test…). Enter all hosts in the cluster where an Oracle VM can run. Tick the groups you want to remove and click “Delete selected”.
  3. Benchmark: choose a scenario (per-core performance ratio). Sensitivity and target savings show which ratio is needed.
  4. Comparison: current x86 versus Power, per group.
  5. New environment (tinted background): configuration of new x86 and new Power servers. By default the new environment follows the current one: it is sized from step 2 and the scenario chosen in step 3. If you tick “New environment independent of the current one”, only the two configurations you enter in step 5 are compared, with no link to steps 2–4 (e.g. a new project or ready-made quotes for both systems).
  6. Infrastructure and TCO of the new x86 and new Power environments.
  7. TCO by year and the year Power becomes cheaper. The summary always stays at the top.

Licensing rules that make the difference

Core factorx86 Intel/AMD = 0.5; IBM Power10 = 1.0. Verify Power11 in the current Oracle Processor Core Factor Table.
x86: soft partitioningVMware, Hyper-V and KVM are not a licensing boundary. All cores of every host in the cluster where an Oracle VM can run must be licensed.
Power: hard partitioningPowerVM LPARs (dedicated/capped) are recognized. The calculator licenses the active Power cores dedicated to Oracle: active cores per server minus cores for non-Oracle LPARs.
Live Partition MobilityWith LPM enabled, Oracle requires licenses for all active cores on the source and target servers. The calculator then licenses all active cores on all Power servers.
Break-evenBecause of the 1.0 vs 0.5 factor, Power needs more than 2× better per-core performance for its per-core licenses to be cheaper.
Used coresExisting x86 is licensed on every host core, while new environments are sized on peak usage plus headroom for growth.
Passive failover and DRA failover-only server may run up to 10 days a year without a license. DR with Data Guard and Test/Dev must be licensed.
Standard Edition 2Licensed per socket (max. 2 sockets); for SE2, Power brings no license savings. In step 5, SE2 servers are entered separately from EE servers. DR for an Enterprise database must be Enterprise Edition, because Data Guard exists only in EE.
Existing licensesDropping support on part of the licenses is subject to Oracle repricing rules. Verify before quoting.
All figures, licensing factors and performance ratios are estimates and vendor/benchmark claims for sales preparation. Before a binding offer, confirm them with a PoC and in writing with Oracle and IBM for the specific configuration.

Customer's current x86 environment

One row is a group of identical servers. The rows are samples — replace them with the customer's data. The table is wide: scroll left and right; the delete checkbox and host count are on the left.

Licensed cores = hosts × sockets × coresE.g. 4 hosts × 2 sockets × 32 cores = 256. With VMware, Oracle requires licenses for every host in the cluster, so enter the total number of hosts. Licenses = 256 × 0.5 = 128.
Peak CPU (%)Highest CPU load on these hosts during the busiest period (from vROps, AWR or monitoring; ideally the 95th percentile). It does not change current x86 licenses; it sizes the new Power and new x86 environments. Empty = 100%.
Used cores = licensed × peak CPU % × (1 + headroom)E.g. 256 × 40% × 1.2 = 123. This number feeds the benchmark: 123 ÷ 3.5 = 36 Power cores. Growth headroom is set in step 1.
